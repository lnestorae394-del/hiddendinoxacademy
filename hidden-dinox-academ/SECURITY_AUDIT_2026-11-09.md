# Аудит безопасности и надёжности — HIDDEN DINOX ACADEMY 2.0 (09.11.2026)

Метод: чтение кода серверной части и страниц, автоматический поиск опасных конструкций, воспроизведение проблем тестами на поддельных данных (Firestore, хранилище, токены — всё в памяти). Production, реальные балансы, платежи и сообщения пользователям не затрагивались.

## Проверено, замечаний нет
- Роли и права: строгая иерархия, назначить можно только роль ниже своей; самоповышение, повышение равного/высшего, блокировка равного/высшего и самоблокировка запрещены; причина блокировки обязательна (тесты `security-academy`).
- Административные API и Video Studio: каждый маршрут требует токен; поддельные токены, пустой заголовок, чужая схема, несуществующий пользователь и студент получают отказ на ВСЕХ маршрутах (перебор таблицы маршрутов).
- Доступ к урокам: только опубликованное, проверка активации академии на сервере.
- Ссылки: только https, список разрешённых хостов, без логина/пароля в адресе; открытого перенаправления нет; исходящих запросов по адресам из данных пользователя нет (SSRF); нет `eval`, `exec`, `child_process`.
- CORS: не включён (только свой домен). CSRF: авторизация заголовком `Authorization: Bearer`, куки не используются — защита не требуется.
- Video Studio: проверка формата, размера и заголовка файла; multipart — проверка размера и ETag каждой части, защита от повторного завершения, отмена, автоочистка зависших; подписанные ссылки с ограниченным сроком; удаление проекта не выходит за префикс проекта (в т.ч. при подделанном документе); секреты не попадают в журнал и ответы.
- Клиентский код не работает с Firestore напрямую, поэтому полный запрет в правилах ничего не ломает.

## Оставшиеся риски и что не удалось проверить
1. **Правила Firestore не применены.** Живые правила вашего проекта мне неизвестны. Правила складываются по «ИЛИ»: если в них есть широкое разрешение (например `allow read, write: if true`), его нужно удалить в консоли Firebase → Firestore → Rules, иначе запрет не подействует. Файл не проверялся на эмуляторе Firebase.
2. **`package-lock.json` не обновлён** (нет доступа к реестру npm); подделывать его я не стал. Нужно выполнить `npm install` у себя и закоммитить.
3. **Не проверялись** реальные Firebase, R2, Render, Telegram, Groq, Claude; тесты используют поддельные сервисы.
4. Старые боты AI BOOST (`public/bot`) в проекте отсутствуют, их код не аудировался.
5. Содержимое `deposits.json`/`traders.json` на сервере могло быть изменено через прежний открытый `/deposit` до исправления — стоит просмотреть файл `deposits.json` на Render на подозрительные записи.

## Новые переменные окружения (необязательные)
`VIDEO_STUDIO_OWNER_ONLY=1` — администратор видит только свои проекты. `ADMIN_DASH_CACHE_MS` — срок кэша сводки админки (по умолчанию 15000, `0` — без кэша).
Для старого маршрута `/deposit` нужен тот же `POCKET_POSTBACK_SECRET`, что и для `/postback`.
