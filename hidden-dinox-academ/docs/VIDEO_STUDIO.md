# HIDDEN DINOX VIDEO STUDIO 2.0

Закрытый сайт (роли admin и owner, проверка на сервере): загрузка записи TikTok LIVE → ИИ находит сильные моменты → вертикальные ролики 1080×1920 с хуком, субтитрами и оформлением Hidden Dinox → редактор → экспорт → готовый MP4 приходит в Telegram.
Вход — та же сессия Firebase, что и в админ-панели. Firebase остаётся для входа, ролей и метаданных (Firestore); **все файлы хранятся в Cloudflare R2** (бакет приватный, доступ только по подписанным ссылкам). Тариф Blaze не нужен.

## Интерфейс
Боковая навигация, верхняя панель (состояние R2, система, активная обработка, уведомления, профиль), рабочая область на всю ширину, мобильная версия.
- **Обзор** — проекты, готовые ролики, очередь, ошибки за 7 дней, объём файлов, расход месяца, состояние R2/обработки/FFmpeg, последние проекты и действия. Только реальные данные.
- **Проекты** — поиск, фильтр, сортировка, сетка/список, превью, повторный анализ, удаление с подтверждением, скачивание результата. Проект и клип открываются по адресу (`#/projects/<id>/<клип>`), обновление страницы ничего не теряет. Внутри проекта — редактор клипов (предпросмотр 9:16, шкала обрезки, хук с вариантами ИИ, субтитры, кадр, точный предпросмотр, сборка, Telegram).
- **Загрузки** — несколько файлов, общий прогресс, скорость, оставшееся время, повтор, отмена, прерванные загрузки.
- **Очередь** — Ожидают / Выполняются / Завершены / Ошибки / Отменены, этап и честный прогресс (если процент неизвестен — показывается только этап), повтор неудачных.
- **Шаблоны** — сохранённые наборы оформления (применить / удалить) и редактор оформления.
- **Медиатека** — исходные записи, готовые ролики, логотипы, шаблоны; поиск, фильтры, удаление готового файла.
- **История** — готовые видео со статусом Telegram.
- **Аналитика** — графики по дням, среднее время этапов, доставка в Telegram, расходы по месяцам.
- **Настройки** — Общие, Хранилище, Обработка, Брендинг, Telegram, Безопасность, Диагностика. Каждый подраздел и каждая карточка загружаются независимо: сбой одного запроса не ломает остальное.

## Как читать сообщения о хранилище (Настройки → Хранилище)
| Сообщение | Причина и что сделать |
|---|---|
| «не заданы переменные: …» | не добавлены `R2_*` в Render |
| «R2 отклонил запрос проверки (HTTP 400)» | чаще всего неверный `R2_ENDPOINT` (в адресе не должно быть имени бакета) или `R2_REGION` (нужен `auto`) |
| «отклонило ключи доступа (HTTP 403)» | неверные ключ/секрет или у токена нет прав Object Read & Write на этот бакет |
| «бакет не найден» | неверный `R2_BUCKET` или ID аккаунта в `R2_ENDPOINT` |
| «Нет соединения» | неверный `R2_ENDPOINT` |
| «Не установлены пакеты AWS SDK» | не выполнен `npm install` и коммит `package-lock.json` |
К каждому сообщению добавляется «Проверка адреса без ключей»: если бакет по адресу найден, ошибка в ключах/правах; если нет — в адресе или имени бакета.
Кнопки: **Проверить соединение** (реальный запрос к бакету), **Тест записи и чтения** (тестовый файл ≈17 МБ двумя частями, подписанная ссылка, CORS, ETag; всё удаляется), **Настроить CORS и очистку** (нужен токен Admin Read & Write; иначе покажет готовый JSON для панели Cloudflare).

## Загрузка до 5 ГБ (S3 Multipart)
Сервер создаёт загрузку и выдаёт подписанные ссылки на части (16 МиБ; файл 5 ГБ = 320 частей); браузер грузит по 3 части параллельно прямо в R2; при завершении сервер сверяет список с тем, что лежит в R2 (все части, размеры, ETag), защищён от двойного завершения. Обрыв — выберите тот же файл, догрузятся недостающие части. Отмена вызывает AbortMultipartUpload; просроченные загрузки прерываются автоматически.

## Переменные Render (staging)
```
VIDEO_STUDIO_ENABLED=1
VIDEO_STUDIO_STORAGE=r2
VIDEO_STUDIO_ORIGIN=https://hidden-dinox-video-staging.onrender.com
R2_ENDPOINT=https://<ID_аккаунта>.r2.cloudflarestorage.com     (без имени бакета)
R2_ACCESS_KEY_ID=...        R2_SECRET_ACCESS_KEY=...            (вводить только в панели Render)
R2_BUCKET=hidden-dinox-videos

```
Нужны также (уже есть): `GROQ_API_KEY`, `ANTHROPIC_API_KEY`, `TELEGRAM_BOT_TOKEN`, `ADMIN_TELEGRAM_ID`. FFmpeg: Docker `deploy/Dockerfile.render` или `npm install ffmpeg-static ffprobe-static`.

## Безопасность
Все маршруты `/api/video-studio/*` проверяют токен Firebase, блокировку и роль на сервере; студенты, менторы и модераторы получают отказ. Путь файла задаёт сервер; удаление объектов ограничено префиксами проекта и `video-studio/`. Секреты не попадают в браузер, ответы API, журнал и сообщения. Подписанные ссылки действуют ограниченное время. Раздел Настройки → Безопасность содержит проверку, что API отклоняет запросы без токена и с поддельным токеном.

## Тесты
`sh tests/video-studio-run-all.sh` — строгий запуск (пропуск не считается пройденным): Node-тесты (в т.ч. весь конвейер на настоящем FFmpeg) и страница в Chromium. Внешние сервисы в тестах — подделки (Firestore, S3/R2, Groq, Claude, Telegram). **Реальный R2 и реальный AWS SDK тестами не проверяются** — для этого есть кнопки в Настройки → Хранилище.


## Живой монитор обработки (раздел «Очередь»)
Сверху раздела — «Обработка сейчас»: для каждого активного задания имя видео, **текущий этап** (проверка, подготовка источника, загрузка файла, подготовка звука, распознавание речи, поиск моментов, нарезка, монтаж, сохранение), **длительность этапа и общее время** (счётчики идут в реальном времени), **время последнего обновления**, состояние исполнителя (работает, свободен, отключён, время работы, свободное место на диске), предупреждения и ошибки. Ниже — очередь с позициями и недавно завершённые задания с **реальным временем каждого этапа**.
- **Проценты показываются только когда они измерены:** скачивание (байты), распознавание (части), нарезка (клипы), монтаж (кадры ffmpeg). У остальных этапов показываются название этапа и индикатор активности: «процент не измеряется».
- Состояние хранится в Firestore, поэтому после обновления страницы или перезапуска сервера оно восстанавливается; страница опрашивает сервер каждые 2 секунды при активной обработке и раз в 6 секунд при простое (опрос надёжнее потоков через прокси Render).
- **Зависание:** если задание не обновлялось более 90 секунд, оно подсвечивается; через 2 минуты без heartbeat аренда истекает и задание автоматически перехватывается.
- В «Аналитике» — среднее время этапов по реальным измерениям.

## Надёжность и скорость обработки
- У каждой команды ffmpeg есть таймаут (по умолчанию 30 мин, `VIDEO_STUDIO_FFMPEG_TIMEOUT_MIN`): зависший процесс останавливается, задание повторяется, а не висит до общего лимита (90 мин, `VIDEO_STUDIO_JOB_MAX_RUNTIME_MIN`). У запросов к Groq, Claude и Telegram таймауты были и раньше.
- **Сборка ролика, окно предпросмотра и точный предпросмотр больше не скачивают исходник целиком.** Для записей от 256 МБ ffmpeg читает нужные байты по подписанной ссылке (HTTP Range) с переподключением при обрыве; при сбое ссылки автоматически используется скачивание файла. Параметры: `VIDEO_STUDIO_REMOTE_INPUT=0` — выключить, `VIDEO_STUDIO_REMOTE_MIN_MB` — порог (по умолчанию 256). В тесте с файлом 15 МБ и вырезкой 3 секунды с конца файла (худший случай: служебные данные MP4 в конце) прочитано 31% файла; у больших записей доля заметно меньше.
- Анализ по-прежнему скачивает запись один раз (нужен звук и нарезка окон), расшифровка и ответ ИИ кэшируются: повторный анализ не платит дважды.
- Очередь: сохранение в Firestore, аренда и heartbeat, перехват зависших, защита от двойного выполнения, отмена, повтор с задержкой; временные файлы удаляются после каждого задания, исходная запись при ошибках не удаляется (проверено тестами).


## Рабочий процесс: от стрима до готовых клипов
**Путь:** Загрузить стрим → выбрать количество клипов → «Начать нарезку» → получить клипы → открыть «Готовые клипы» → исправить нижний текст и задание → «Сохранить» → выбрать клипы → «Импорт в Telegram».
- **Проекты → «Начать нарезку»:** название проекта, исходное видео, число клипов (3, 5, 10, 15, 20 или своё, 1–50), галочка «сразу собрать видео». Система находит **не больше** заданного числа; если сильных моментов меньше, дубликаты не создаются, проект показывает «Запрошено N · найдено M». Расход анализа показывается до запуска.
- **Найденные моменты** (в проекте) → **Клипы в работе** (статусы «Ожидает редактирования», «Нужны правки», «В работе у монтажёра», «На проверке») → **Готовые клипы** (собранное видео; «Готов», «Утверждён»). Все клипы всех проектов — в разделе «Готовые клипы»: карточка с превью, названием, длительностью, нижним текстом, статусом, монтажёром, датой изменения; поиск, фильтры, вкладки по статусам, «Выбрать все», «Назначить монтажёра», «Импорт в Telegram» (кнопка справа вверху).
- **Автосборка:** после нарезки каждый клип сам ставится в очередь на сборку (приоритет ниже ручных; в Telegram автоматически не отправляется). Выключается в форме «Начать нарезку».
- **Редактор клипа:** «Текст внизу видео» (до 3 строк, размер, положение, удаление) попадает в итоговый рендер; призыв «Хочешь с нами? Смотри профиль» по умолчанию стоит ниже субтитров, положение и размер настраиваются; блок «Статус и задание монтажёру» (7 статусов, монтажёр, задание до 5000 символов, комментарий); кнопка «Сохранить» и индикатор «Сохранено / Есть несохранённые изменения». При уходе со страницы клипа несохранённое сохраняется автоматически. Под результатом всегда написано, собрано ли видео, устарело ли оно и что нажать дальше.
- **Где хранится:** рабочие данные — в документе клипа (`workflow`: статус, задание, комментарий, монтажёр, версия; `deliveries`), тексты и правки — в `videoStudioEdits` (единый источник, копий нет), монтажёры — `videoStudioEditors`, журнал изменений — `videoStudioClipEvents`. Параллельной системы хранения нет.

## Монтажёры
Раздел «Монтажёры»: добавить, изменить, отключить, удалить (с подтверждением снимает назначения), очередь заданий каждого — **только его клипы**. Клипы назначаются из «Готовых клипов» (несколько сразу) или в редакторе. Рядом с монтажёром виден статус Telegram: «выключен», «не привязан» или «привязан».

## Telegram: отдельный бот Video Studio
Переменные Render (токен хранится только на сервере и не попадает в браузер, Firestore и журнал):
```
VIDEO_STUDIO_TELEGRAM_ENABLED=0            (1 — включить)
VIDEO_STUDIO_TELEGRAM_BOT_TOKEN=
VIDEO_STUDIO_TELEGRAM_WEBHOOK_SECRET=      (случайная строка от 16 символов)
VIDEO_STUDIO_TELEGRAM_OWNER_CHAT_ID=       (ваш числовой Telegram ID — для «Себе»)
VIDEO_STUDIO_TELEGRAM_BOT_USERNAME=        (необязательно: имя бота без @, для ссылки привязки)
```
Пока бот не включён, интеграция выключена, кнопка «Импорт в Telegram» объясняет, как её включить, остальные функции работают.
- **Вебхук:** адрес `https://<ваш-сайт>/api/video-studio/telegram/webhook` (виден в Настройки → Telegram). Telegram нужно один раз сказать этот адрес и секрет (в адресной строке браузера, подставив свои значения): `https://api.telegram.org/bot<ТОКЕН>/setWebhook?url=<АДРЕС ВЕБХУКА>&secret_token=<СЕКРЕТ>`. Вебхук принимает только запросы с верным секретом и только личные чаты.
- **Привязка монтажёра:** «Монтажёры» → «Привязать Telegram» → одноразовый код (30 минут) или ссылка; монтажёр отправляет боту `/start КОД`. Сохраняется числовой Telegram ID (имя пользователя не используется), в базе — только хэш кода. Команда `/tasks` показывает монтажёру только его клипы.
- **«Импорт в Telegram»:** себе, конкретному монтажёру (уйдут только назначенные ему клипы) или каждому по назначению. Отправляется последнее собранное видео, подпись с названием и статусом и отдельным сообщением задание (длинное делится на части). Назначение проверяется на сервере при постановке и ещё раз в момент отправки.

## API рабочего процесса (все, кроме вебхука, — только для админов, проверка на сервере)
`GET /clips`, `PUT /clips/:id/workflow`, `POST /clips/assign`, `GET /clips/:id/history`, `GET /activity`, `GET|POST /editors`, `PUT|DELETE /editors/:id`, `GET /editors/:id/queue`, `POST /editors/:id/link`, `DELETE /editors/:id/telegram`, `GET /telegram/status`, `POST /telegram/dispatch`, `POST /api/video-studio/telegram/webhook` (секрет Telegram). Расширены: `POST /projects/:id/analyze` (`title`, `target_clips`, `auto_render`), правки клипа (`set_caption`, `reset_caption`, `set_cta` с положением и размером), `GET /history`, `GET /dashboard`.


## Нагрузка на Firestore (бесплатный план: 50 000 чтений в сутки)
Что было: каждый API-запрос читал документ пользователя, настройки (7 документов) читались без кэша, исполнитель делал цикл каждые 5 секунд (10 чтений), каждая вкладка каждые 2,5–8 секунд читала **все** задания, монитор и обзор заново читали одни и те же коллекции.
Что сделано:
- **Исполнитель:** при пустой очереди пауза растёт 5 → 60 с (`VIDEO_STUDIO_IDLE_POLL_SEC`, по умолчанию 60); постановка, повтор и отмена будят его сразу (проверено: задание берётся быстрее 0,4 с); во время работы он ничего не опрашивает.
- **Кэш в памяти** (всё сбрасывается сразу при ЛЮБОМ изменении через API и при смене состояния задания исполнителем, поэтому готовый или ошибочный статус не «застревает»): настройки 5 минут, пользователь 15 с, снимки коллекций для обзора/аналитики/клипов/монтажёров/истории 10 с, монитор 3 с. Переменные: `VIDEO_STUDIO_SETTINGS_CACHE_MS`, `VIDEO_STUDIO_AUTH_CACHE_MS`, `VIDEO_STUDIO_SNAP_CACHE_MS`, `VIDEO_STUDIO_MONITOR_CACHE_MS` (0 — выключить). Блокировка пользователя или смена роли вступает в силу не позже чем через 15 с.
- **Ограниченные запросы:** `/jobs` — активные + 80 последних (не растёт с числом заданий); `/jobs?active=1` — только активные (в простое 1 чтение); `/health` считает очередь счётчиком (1 чтение); монитор не читает проекты по одному.
- **Интерфейс:** опрашивает ОДНА видимая вкладка (лидер), остальные получают данные через localStorage; скрытая вкладка не опрашивает; опрос заданий 4 с при обработке и 30 с в простое, health 60 с, монитор 3 с / 30 с; при ошибке пауза нарастает и учитывает `Retry-After`.
- **RESOURCE_EXHAUSTED:** API отвечает 429 с причиной (`daily_quota` / `contention` / `rate_limit`) и паузой 60 с; исполнитель при такой ошибке делает паузу 5 минут без повторов, задание повторяется через ≈15 минут и конечное число раз (3).
- **Диагностика:** Настройки → Диагностика → «Чтения Firestore»: кто и сколько читает, прогноз на сутки, ошибки RESOURCE_EXHAUSTED с причиной; строка в журнале Render раз в 10 минут. Скрипт `node tests/tools/video-studio-read-audit.js [--optimized]` считает чтения на каждый вызов и нагрузку по частоте опроса (на тестовой базе).

## Откат
Уберите `VIDEO_STUDIO_ENABLED` — раздел выключится. Данные (`videoStudio*` в Firestore и `video-studio/` в бакете) остаются.
