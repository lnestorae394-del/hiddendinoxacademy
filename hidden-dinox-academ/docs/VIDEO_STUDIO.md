# HIDDEN DINOX VIDEO STUDIO

Закрытый раздел админ-панели: загрузка записи TikTok LIVE → ИИ находит сильные моменты → вертикальные ролики 1080×1920 с хуком, субтитрами и оформлением Hidden Dinox → редактор → экспорт → **готовый MP4 приходит вам в Telegram**.
Открывается из админ-панели (пункт «Video Studio»), использует ту же сессию Firebase, доступен только admin и super_admin (проверка на сервере).

## Где что хранится
- **Firebase** — только вход (Authentication), роли и метаданные проектов, очереди и клипов (Firestore). Firebase Storage и тариф Blaze для видео НЕ нужны.
- **Cloudflare R2** (бакет `hidden-dinox-videos`) — все файлы: исходные записи, превью-окна, готовые ролики, расшифровки. Бакет приватный: файлы отдаются только подписанными ссылками с ограниченным сроком (15 минут; для ссылки в Telegram — 24 часа).
- Переключатель: `VIDEO_STUDIO_STORAGE=r2`. Если выбран r2, переход на Firebase Storage никогда не происходит: при ошибке настройки страница и логи показывают точную причину.

## Как работает загрузка (S3 Multipart Upload, до 5 ГБ и больше)
1. Браузер просит сервер начать загрузку. Сервер проверяет права администратора, формат, размер, лимиты, доверенный адрес страницы и создаёт multipart-загрузку в R2.
2. Размер части выбирает сервер: **16 МиБ** (файл 5 ГБ = 320 частей; ограничения S3/R2: часть ≥ 5 МиБ кроме последней, ≤ 10 000 частей, R2 требует одинаковый размер всех частей, кроме последней).
3. Сервер выдаёт подписанные ссылки на части (пачками; каждая действует 1 час, выдаются только для этого проекта). Браузер грузит **по 3 части параллельно прямо в R2**, показывает прогресс и скорость. Неудавшаяся часть повторяется (до 6 попыток, с новой ссылкой, если старая истекла).
4. При завершении страница отправляет список частей (номер и ETag). Сервер **сам сверяет его с тем, что реально лежит в R2** (ListParts): все части на месте, размеры верны, ETag совпадают. Только потом вызывает CompleteMultipartUpload, проверяет итоговый размер и заголовок файла (MP4/MOV) и ставит проверку видео в очередь. Если браузер не смог прочитать ETag (не настроен CORS), сервер берёт ETag из R2 сам.
5. Повторное завершение одной загрузки невозможно (блокировка в Firestore). Отмена вызывает AbortMultipartUpload и удаляет начатые части.
6. **Возобновление:** если загрузка оборвалась (закрыли вкладку, пропал интернет), выберите тот же файл ещё раз: страница узнает у сервера, какие части уже лежат в R2, и догрузит только недостающие — даже с другого компьютера.
7. **Очистка:** сервер раз в час прерывает просроченные (48 часов) незавершённые загрузки, раз в сутки — страховочная чистка зависших multipart-загрузок старше 4 суток; кнопка «Настроить хранилище» добавляет в бакет правило автоматической отмены через 3 дня.

## Настройка staging (по шагам)
1. **Переменные в Render** (Environment) — значения секретов вводите ТОЛЬКО в панели Render:
```
VIDEO_STUDIO_ENABLED=1
VIDEO_STUDIO_STORAGE=r2
VIDEO_STUDIO_ORIGIN=https://hidden-dinox-video-staging.onrender.com
R2_ENDPOINT=https://<ID_аккаунта>.r2.cloudflarestorage.com      (без имени бакета и без пути)
R2_ACCESS_KEY_ID=...
R2_SECRET_ACCESS_KEY=...
R2_BUCKET=hidden-dinox-videos
R2_REGION=auto
```
Нужны также (уже есть): `GROQ_API_KEY`, `ANTHROPIC_API_KEY`, `TELEGRAM_BOT_TOKEN`, `ADMIN_TELEGRAM_ID`. Токен R2: Cloudflare → R2 → Manage API tokens → права **Object Read & Write** на бакет `hidden-dinox-videos`.
2. **Зависимости.** Добавлены `@aws-sdk/client-s3` и `@aws-sdk/s3-request-presigner`. В папке проекта выполните `npm install` (обновит `package-lock.json`), закоммитьте оба файла. Если в Render в Build Command стоит `npm ci`, замените на `npm install`. Если сборка пишет, что нужен Node 20 или новее, добавьте переменную `NODE_VERSION=22`.
3. **FFmpeg** (как и раньше): Docker с `deploy/Dockerfile.render` или `npm install ffmpeg-static ffprobe-static`.
4. **CORS бакета** (обязательно для загрузки из браузера). Вариант A: Video Studio → Настройки → «Настроить хранилище (CORS)». Для этого нужен токен с правом администрирования бакета (Admin Read & Write); с обычным токеном Object Read & Write кнопка покажет готовый JSON. Вариант B (всегда работает): Cloudflare → R2 → бакет → Settings → **CORS Policy → Add CORS policy** → вставьте содержимое `deploy/r2-cors.json` (разрешён только адрес staging, не `*`; заголовок **ETag** открыт для браузера) → Save.
5. Правило очистки зависших загрузок: см. `deploy/r2-lifecycle.md` (или кнопка из шага 4A).
6. Deploy. Откройте админ-панель → Video Studio: сверху появится жёлтый список «Не всё настроено» с точной причиной, если что-то не готово; раздел Настройки → «Диагностика» показывает статус R2 (подключено / причина ошибки).
7. Telegram — один раз: Настройки → Telegram → «Проверить подключение» → нажать Start у бота → ввести Chat ID → «Отправить тестовое сообщение».

## Что значат сообщения о хранилище
| Сообщение | Причина |
|---|---|
| «не заданы переменные: …» | не добавлены R2_* в Render |
| «R2_ENDPOINT должен быть без имени бакета» | в адрес добавлено `/hidden-dinox-videos` — уберите |
| «Хранилище отклонило ключи доступа» | неверные ключ/секрет или у токена нет прав на этот бакет |
| «Бакет … не найден» | неверный R2_BUCKET или токен выдан на другой бакет |
| «Нет соединения с хранилищем» | неверный R2_ENDPOINT (ID аккаунта) |
| «Не установлены пакеты AWS SDK» | не выполнен `npm install` и коммит package-lock.json |
| загрузка прерывается, подсказка про CORS | не настроен CORS бакета (шаг 4) |

## Безопасность
- Все маршруты `/api/video-studio/*`: проверка токена Firebase, блокировки и роли admin/super_admin на сервере; ссылки на части выдаются только для проекта администратора; путь файла задаёт сервер (чужие префиксы недоступны); удаление по префиксу работает только внутри `video-studio/`.
- Секреты (ключи R2, токен бота, ключи ИИ) берутся только из окружения; в Firestore, ответы API, журнал и сообщения об ошибках не попадают. Бакет не публичный. Сервер не обращается по ссылкам, которые присылает пользователь (SSRF исключён).
- Доверенный адрес страницы: `VIDEO_STUDIO_ORIGIN` (и адрес самой страницы); чужой Origin получает отказ до создания загрузки.

## Тесты
`sh tests/video-studio-run-all.sh` — строгий запуск (пропущенный тест не считается пройденным). Все внешние сервисы в тестах — подделки: Firestore, Groq, Claude, Telegram Bot API и **S3/R2 (поддельный S3 с правилами multipart; настоящий AWS SDK в тестах не запускается)**. Подробнее о том, что проверено и что требует проверки на реальном R2, — в сообщении о результатах.

## Проверка R2 на реальном бакете (делает администратор)
1. Настройки → Диагностика: «Хранилище видео: Cloudflare R2 подключено (бакет hidden-dinox-videos)».
2. Загрузите файл 20–50 МБ → проект перейдёт в «Проверка видео», затем «Готово к анализу». Если загрузка обрывается — смотрите подсказку про CORS.
3. Загрузите файл ~1–2 ГБ: проверьте прогресс, оборвите загрузку (закройте вкладку), откройте страницу, выберите тот же файл — должна продолжиться с места остановки.
4. Cloudflare → R2 → бакет → в Objects появится `video-studio/<uid>/<проект>/source/original.mp4`; незавершённых загрузок после успешной не остаётся.

## Откат
Уберите `VIDEO_STUDIO_ENABLED` — маршруты и обработка выключатся. Файлы в R2 и данные `videoStudio*` остаются; удаляйте вручную.
